# Research Quality Layer V1 policy

## Scope

This is a research-only quality adapter for Revenue YoY validation. It does not repair prices,
infer corporate actions, alter the production marts, or certify the historical price layer. The
formation universe, factor values, and quintile assignments are frozen before outcome-quality
flags are attached.

The observation key is `(rebalance_date, ticker)`. The source panel is
`stock_analytics.mart_factor_research_monthly`; its scheduled rebalance date is the first 0050
trading date on or after the 15th, and its return endpoint is `next_rebalance_date`.

## Versioned anomaly evidence

`input/research_price_anomalies_v1.csv` is generated by `build_anomaly_input.py` from the
2026-10-12 reverse-QA artifact. Its transition key is
`(ticker, prev_quote_date, quote_date)`. It contains:

- 360 unique transitions for which `abs(adjusted_return) > 0.50` (262 tickers); and
- one separately identified control, ticker 2429 on 2024-07-02, authoritatively classified as an
  adjustment error involving paid subscription rights.

The threshold is an anomaly screen, not evidence that each movement is a corporate action. No
factor is inferred from a price ratio. Source hashes and the generated input hash are recorded in
`input/research_price_anomalies_v1_manifest.json`.

## Quality states

The three flags are `forward_return_quality`, `ma20_quality`, and `ma60_quality`. Their values are:

- `VALID`: the original value is available and no known V1 anomaly intersects its exact interval
  or window;
- `INVALID`: at least one known V1 anomaly intersects the interval or window; and
- `UNKNOWN`: the original value or evidence required to establish usability is unavailable.

`VALID` means “not exposed to the known V1 anomaly set.” It does not mean that the price or
corporate-action history is proven complete. `UNKNOWN` is never promoted to `VALID`.

All anomaly-to-observation links are retained in normalized form in
`output/quality_relationships_v1.csv`. The wide dataset contains JSON provenance fields so that
multiple anomalies are not reduced to an arbitrary single event.

## Forward-return rule

The original monthly label is calculated from adjusted prices at the fixed current and next
rebalance endpoints. Both endpoint raw closes must be observed and positive, and both adjusted
closes must be positive and finite.

An anomaly invalidates a label exactly when:

```text
rebalance_date < anomaly.quote_date <= next_rebalance_date
```

The start is open because a transition ending on the start endpoint is already incorporated into
both subsequent endpoint prices. The end is closed because the anomalous transition is part of the
return measured at the end endpoint.

The original `forward_return` remains untouched. `forward_return_research` equals the original
value only for `VALID`; it is null for `INVALID` and `UNKNOWN`. Invalid values are never set to
zero and never used to remove a security before formation.

## MA20 and MA60 rules

Production computes moving averages over `int_daily_prices_adjusted` with inclusive SQL row
frames `ROWS BETWEEN 19 PRECEDING AND CURRENT ROW` and `ROWS BETWEEN 59 PRECEDING AND CURRENT
ROW`. These are ticker-specific price-table rows, including the production effective-close
carry-forward behavior; they are not calendar-day approximations.

Let the anomalous transition end on price row `e`, and formation occur on row `f`. The feature is
invalid when:

```text
MA20: 0 <= f - e <= 18
MA60: 0 <= f - e <= 58
```

At offsets 19 and 59 the corresponding inclusive window starts on the post-event quote; no
pre-event price basis remains. This exact rule is narrower than the earlier conservative impact
audit, which included offsets 19/59.

## Formation invariance

For the canonical 2018–2025 Revenue YoY test, the adapter reproduces the existing process:

- exclude benchmark 0050;
- keep finite `yoy_growth`;
- trim each monthly cross-section to inclusive P1/P99;
- sort by `yoy_growth`, then ticker ascending;
- assign five position-based quantiles; and
- only after assignment, apply return-label eligibility.

Quality flags are attached after formation. No future anomaly information changes membership,
factor values, or quintiles.

## Limitations

1. The 50% threshold is heuristic; genuine market moves may be flagged.
2. Smaller corporate-action errors may remain below the threshold.
3. The historical corporate-action ledger remains incomplete.
4. Retrospective outcome invalidation can create non-random missing labels.
5. `VALID` is bounded by the anomaly source’s historical coverage; it is not proof of cleanliness.
6. This policy supports scoped factor evaluation, not unrestricted tradable-backtest certification.
7. It does not declare the production adjustment layer correct or Price Foundation complete.

## Reproduction

```bash
../research/venv/bin/python audits/corporate_actions/research_quality_v1/build_anomaly_input.py
../research/venv/bin/python audits/corporate_actions/research_quality_v1/test_research_quality_v1.py
../research/venv/bin/python audits/corporate_actions/research_quality_v1/run_quality_layer_v1.py --dry-run
../research/venv/bin/python audits/corporate_actions/research_quality_v1/run_quality_layer_v1.py --execute
```

After the two SELECT-only query outputs exist, local post-processing is resumable without BigQuery:

```bash
../research/venv/bin/python audits/corporate_actions/research_quality_v1/run_quality_layer_v1.py --from-local
```
